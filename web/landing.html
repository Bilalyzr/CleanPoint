Chapter 01 — The incident

The newest backup
is already compromised.

Compromise predates detection. The latest snapshot carries encrypted-like content behind perfectly valid hashes — restoring it reintroduces the incident you are recovering from.

  • Compromise hides upstream of alarms.By the time anything looks wrong, recent snapshots are already poisoned.
  • A hash proves integrity, not cleanliness.SHA-256 says the bytes are unchanged — not that they were safe when captured.
  • Recency bias is expensive.Minutes of RPO saved versus contaminated data restored is a bad trade.

Chapter 02 — The evidence

Behavior tells the truth
telemetry never lies about change.

Every 300-second window is scored against a robust median/MAD baseline. Six explainable signals — never a black box, never a probability.

rules-v1 · risk_index relative score 0 – 1
normal windows attack windows training period
  • .25modified-file ratio
  • .25entropy shift
  • .20rename rate
  • .15extension novelty
  • .10delete rate
  • .05size change

Fixed rules-v1 weights. Missing evidence lowers coverage — it is never imputed, and weights are never redistributed.

Chapter 03 — The defensible point

Safety before recency.
Always.

The selector walks snapshots newest-first and demands four proofs before it will recommend anything:

  1. 01
    Sealed & integrity-verifiedmanifest and every object re-hashed
  2. 02
    Exposure clearno suspicious window closed before capture
  3. 03
    Baseline coverage24 normal windows of history behind it
  4. 04
    Strictly before onsetcaptured earlier than the earliest plausible attack

Among equals, the newest wins. The recovery gap is measured in minutes — and shown, never hidden.

Chapter 04 — The restore

Copied out. Re-hashed.
Proven unchanged.

Restore requires an operator's explicit approval. Output lands in a server-generated isolated directory — the sealed source is verified untouched afterwards.

    Honest limits

    A local simulation, not a production data-protection product. No live malware is ever executed — "encrypted" content is seeded random bytes. Logical immutability is API policy, not WORM storage. Full positioning in docs/limitations.md.
